## 2. 背景と課題

大学の科目では、出席条件、課題、テストなどの評価方法が科目ごとに異なる。学生は次の情報を自分で計算・管理する必要があり、負担が大きい。

- あと何回欠席できるか
- 目標成績に到達するには、残りの課題やテストで何点必要か
- 現在、どの科目が危険な状態にあるか

本システムは、科目ごとの評価方法と実績を一元管理し、目標達成に必要な行動を自動計算して提示することで、この負担を軽減する。

## 3. 目的

本システムの目的は以下のとおりとする。

1. 学生が科目ごとの出席条件と評価方法を登録できるようにする。
2. 学生が出席、テスト、課題の実績を手動で記録できるようにする。
3. 登録情報から、残りの許容欠席回数と目標達成に必要な点数を算出する。
4. 科目ごとの状況を一覧またはダッシュボードで把握できるようにする。

## 4. 対象ユーザー

### 4.1 主対象

- 大学・短期大学・専門学校などで、複数科目の出席と成績を管理する学生
- 自分でシラバスや成績評価方法を確認し、手動で登録できる利用者

### 4.2 利用条件

- メールアドレスとパスワードでアカウントを作成できること
- Webブラウザを利用できること
- 各科目の出席条件、評価割合、実績を把握していること

## 5. 対象範囲

### 5.1 MVPに含む機能

- メールアドレスとパスワードによる認証
- 科目と評価方法の登録・編集
- 出席実績の手動記録
- テスト・課題点数の手動記録
- 残り許容欠席回数の計算
- 目標達成に必要な点数の逆算
- 科目一覧、科目詳細、ダッシュボードでの状況確認

### 5.2 MVPに含まない機能

MVP外の機能候補は、本書の要件と混在させず、[MVP外機能.md](./MVP外機能.md)で管理する。MVPの実装・受け入れ判定には含めない。

## 6. 前提条件・制約

### 6.1 技術上の制約

- フロントエンドおよびサーバー処理にはNext.js 16のApp Routerを使用する。
- 実装言語にはTypeScriptを使用する。
- スタイルにはTailwind CSSを使用する。
- 認証とデータベースにはSupabaseを使用する。
- Node.js 20以上で動作すること。
- Next.jsの仕様判断では、リポジトリ内の `node_modules/next/dist/docs/` を優先する。

### 6.2 環境上の制約

- アプリケーションが利用する環境変数は以下の2つとする。
  - `NEXT_PUBLIC_SUPABASE_URL`
  - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY` はアプリケーションへ設定せず、リポジトリへコミットしない。
- MVPではSupabase Authのメール確認を無効にし、登録後すぐにログイン可能な構成を前提とする。

## 7. ユーザーフロー

### 7.1 初回利用

1. 利用者が新規登録画面を開く。
2. メールアドレスとパスワードを入力する。
3. 登録成功後、ログイン状態でダッシュボードへ移動する。
4. 科目を新規登録する。
5. 出席条件、評価項目、重み、目標成績を設定する。

### 7.2 日常利用

1. 利用者がログインする。
2. ダッシュボードで科目ごとの状況を確認する。
3. 対象科目を選択する。
4. 出席、テスト、課題の実績を記録する。
5. 残り許容欠席回数または目標達成に必要な平均点から、求めたい値を選択する。
6. 自動入力されなかった不足変数がある場合、利用者が値を入力する。
7. 計算結果を確認する。

## 8. 機能要件

### 8.1 認証

| ID | 要件 |
| --- | --- |
| AUTH-01 | 利用者はメールアドレスとパスワードでアカウントを作成できること。 |
| AUTH-02 | アカウント作成に成功した利用者は、ログイン状態でダッシュボードへ移動できること。 |
| AUTH-03 | 登録済み利用者はメールアドレスとパスワードでログインできること。 |
| AUTH-04 | ログイン済み利用者はログアウトできること。 |
| AUTH-05 | 未認証利用者が `/dashboard` または `/subjects` 配下へアクセスした場合、ログイン画面へリダイレクトされること。 |
| AUTH-06 | 認証に失敗した場合、内部情報を露出せず、利用者が理解できるエラーを表示すること。 |
| AUTH-07 | パスワードは8文字以上を必須とすること。 |

### 8.2 科目管理

| ID | 要件 |
| --- | --- |
| SUB-01 | 利用者は自分が登録した科目の一覧を確認できること。 |
| SUB-02 | 利用者は科目名を登録できること。 |
| SUB-03 | 利用者は科目の総授業回数を登録できること。 |
| SUB-04 | 利用者は必要出席率または最大欠席回数を出席条件として登録できること。 |
| SUB-05 | 利用者は出席が成績評価へ影響するかを登録できること。 |
| SUB-06 | 利用者は目標成績の表示名と目標点数を登録できること。逆算には目標点数を使用し、目標成績の表示名は表示専用とする。 |
| SUB-07 | 利用者は登録済みの科目情報と評価方法を編集できること。 |
| SUB-08 | 利用者は他の利用者が登録した科目を閲覧・変更できないこと。 |
| SUB-09 | 利用者は確認操作を経て、自分が登録した科目を削除できること。 |

### 8.3 評価項目管理

| ID | 要件 |
| --- | --- |
| ITEM-01 | 利用者は1科目に複数の評価項目を登録できること。 |
| ITEM-02 | 評価項目には名称、カテゴリ、重み、満点、表示順を設定できること。 |
| ITEM-03 | 評価項目のカテゴリは、出席・課題・テスト・その他から選択できること。 |
| ITEM-04 | 利用者は登録済みの評価項目を編集できること。 |
| ITEM-05 | 科目に設定する評価項目の重み合計は100%を必須とし、100%でない場合は保存を完了できないこと。 |
| ITEM-06 | 評価項目は「項目追加型」と「反復型」の両方を扱えること。 |
| ITEM-07 | 項目追加型では、中間テスト・期末テストなどを個別の評価項目として追加できること。 |
| ITEM-08 | 反復型では、小テスト・課題など同じ評価項目に複数回の実績を追加できること。 |
| ITEM-09 | 利用者は確認操作を経て、登録済みの評価項目を削除できること。 |

「項目追加型」はUI上で評価項目を列・項目として増やす方式を指す。DBの物理カラムを動的に増やすのではなく、評価項目データとして追加する。「反復型」は1つの評価項目に対して第1回、第2回のように実績行を追加する方式とする。

### 8.4 出席記録

| ID | 要件 |
| --- | --- |
| ATT-01 | 利用者は科目ごとに出席実績を手動で登録できること。 |
| ATT-02 | 出席記録には授業日、出席状態、任意のメモを保持できること。 |
| ATT-03 | MVPで扱う出席状態は、出席と欠席の2種類とする。遅刻・公欠の専用フォーマットは用意しない。 |
| ATT-04 | 利用者は科目ごとの出席記録を確認・編集できること。 |
| ATT-05 | 利用者は他の利用者の出席記録を閲覧・変更できないこと。 |
| ATT-06 | 利用者は確認操作を経て、自分の出席記録を削除できること。 |

### 8.5 テスト・課題記録

| ID | 要件 |
| --- | --- |
| SCORE-01 | 利用者は評価項目に対する取得点数を手動で登録できること。 |
| SCORE-02 | 点数記録には評価項目、取得点数、記録日、任意のメモを保持できること。 |
| SCORE-03 | 利用者は科目ごとのテスト・課題記録を確認できること。 |
| SCORE-04 | 点数は0以上かつ設定された満点以下の数値として扱い、不正な値を受け付けないこと。 |
| SCORE-05 | 利用者は他の利用者の点数記録を閲覧・変更できないこと。 |
| SCORE-06 | 項目追加型の評価項目には1件の実績を、反復型の評価項目には複数回の実績を登録できること。 |
| SCORE-07 | 利用者は登録済みの点数記録を編集できること。 |
| SCORE-08 | 利用者は確認操作を経て、自分の点数記録を削除できること。 |
| SCORE-09 | 反復型の複数実績は、各回を100点換算したうえで単純平均し、評価項目の得点として扱うこと。 |

### 8.6 計算入力と不足変数の補完

| ID | 要件 |
| --- | --- |
| CALC-COMMON-01 | 利用者は「残り許容欠席回数」または「目標達成に必要な平均点」から、求めたい値を選択できること。 |
| CALC-COMMON-02 | システムは、選択した計算に必要な入力変数をフォームとして表示すること。 |
| CALC-COMMON-03 | 登録済みの科目設定や実績から取得できる変数は、自動的に初期入力すること。 |
| CALC-COMMON-04 | 計算に必要な変数が不足している場合、不足項目を明示し、利用者が手動で入力できること。 |
| CALC-COMMON-05 | 必要な変数が揃うまでは計算結果を確定値として表示しないこと。 |
| CALC-COMMON-06 | 計算には画面上で確認できる現在の入力値を使用し、保存済み値を暗黙に上書きしないこと。 |
| CALC-COMMON-07 | 手動補完した変数は既定では計算専用の一時入力とし、利用者が明示的に保存操作をした場合だけ科目設定または実績として保存すること。 |

### 8.7 出席状況の計算

| ID | 要件 |
| --- | --- |
| CALC-ATT-01 | システムは総授業回数、出席数、欠席数、必要出席率、最大欠席回数を入力として扱えること。 |
| CALC-ATT-02 | システムは現在の出席率を算出できること。 |
| CALC-ATT-03 | システムは残りの許容欠席回数を算出できること。 |
| CALC-ATT-04 | 必要出席率と最大欠席回数が両方設定されている場合、より厳しい条件を採用すること。 |
| CALC-ATT-05 | 出席条件が未設定または計算不能の場合、誤った数値を表示せず、その状態を利用者へ示すこと。 |
| CALC-ATT-06 | 危険度は、残り2回以上を「順調」、残り1回を「注意」、残り0回を「危険」、マイナスを「条件超過」と判定すること。 |
| CALC-ATT-07 | 現在の出席率は小数第1位まで表示し、許容欠席回数は小数を切り捨てた整数として算出すること。 |

### 8.8 目標点数の逆算

| ID | 要件 |
| --- | --- |
| CALC-SCORE-01 | システムは評価項目の重み、満点、現在の取得点数と、科目の目標点数を入力として扱えること。 |
| CALC-SCORE-02 | システムは残りの評価項目で必要となる点数を100点換算の平均点として算出できること。 |
| CALC-SCORE-03 | システムは目標点数が達成可能か判定できること。 |
| CALC-SCORE-04 | すでに目標を達成している場合、「目標達成済み」として必要平均点と区別して表示すること。 |
| CALC-SCORE-05 | データ不足または計算不能の場合、誤った数値を表示せず、その状態を利用者へ示すこと。 |
| CALC-SCORE-06 | 目標点数が未入力の場合は逆算を行わず、不足変数として入力を求めること。 |
| CALC-SCORE-07 | 必要平均点は小数第1位まで表示すること。入力点数は小数第2位まで扱えること。 |

## 10. データ要件

### 10.1 科目

科目は利用者に属し、以下の情報を保持する。

- 科目名
- 総授業回数
- 必要出席率
- 最大欠席回数
- 出席が成績評価へ影響するか
- 目標成績の表示名
- 目標点数
- 作成日時・更新日時

### 10.2 評価項目

評価項目は科目に属し、以下の情報を保持する。

- 名称
- カテゴリ（出席・課題・テスト・その他）
- 入力方式（項目追加型・反復型）
- 重み
- 満点
- 表示順

### 10.3 出席記録

出席記録は科目および利用者に属し、以下の情報を保持する。

- 授業日
- 出席状態（出席・欠席）
- メモ
- 作成日時

### 10.4 点数記録

点数記録は評価項目および利用者に属し、以下の情報を保持する。

- 取得点数
- 記録日
- メモ
- 作成日時

項目追加型の評価項目は1件の点数記録と対応させ、反復型の評価項目は複数件の点数記録と対応できる構造とする。

### 10.5 データ所有権

- 全テーブルでRow Level Securityを有効にする。
- 利用者は自分の科目と、その科目に紐づく評価項目・出席記録・点数記録だけを操作できること。
- 科目、評価項目、出席記録、点数記録は、利用者の確認操作後に削除できること。
- 科目を削除した場合、紐づく評価項目・出席記録・点数記録も整合性を保って削除すること。
- 利用者の削除時には、その利用者に属する科目と実績データを削除できるデータ構造とする。

## 11. 非機能要件

### 11.1 セキュリティ

- 認証が必要な画面を未認証利用者へ表示しないこと。
- SupabaseのRLSにより、利用者間のデータを分離すること。
- Service Role Keyなど、RLSを迂回可能な秘密情報をクライアントへ公開しないこと。
- 認証・DBエラーの詳細をそのまま利用者へ表示しないこと。
- 認証セッションをCookieで安全に維持・更新すること。

### 11.2 保守性

- TypeScriptによる型チェックが成功すること。
- ESLintによる静的解析を実行できること。
- UI、データアクセス、計算ロジックを分離すること。
- 一ファイル一責務を基本とし、画面、フォーム、DBクエリ、計算処理を適切に分割すること。
- Next.js 16で非推奨となった規約を使用しないこと。

### 11.3 可用性・エラー処理

- データが0件の場合でも画面が正常に表示されること。
- 入力エラーとシステムエラーを区別して表示できること。
- DB取得に失敗した場合、誤ったデータを正常値として表示しないこと。

### 11.4 操作性

- 主要画面から科目登録、実績記録、状況確認へ移動できること。
- 入力項目には内容が分かるラベルを表示すること。
- 計算結果は数値だけでなく、危険・達成済み・達成不可能・計算不能などの状態も表示すること。

### 11.5 対応環境

- 最新版のGoogle Chrome、Safari、Microsoft Edgeを対応ブラウザとする。
- スマートフォン表示は画面幅375px以上を保証範囲とする。
- 画面幅375px以上では、主要な登録・記録・計算・確認操作を横スクロールに依存せず実行できること。

## 12. 受け入れ条件

### 12.1 認証

- 新規利用者が登録後にダッシュボードへ移動できる。
- 登録済み利用者がログイン・ログアウトできる。
- 未認証状態で保護対象URLを開くとログイン画面へ移動する。
- 8文字未満のパスワードでは新規登録できない。

### 12.2 科目設定

- 科目名、出席条件、評価項目、重み、目標点数を保存できる。
- 保存した科目が科目一覧とダッシュボードへ表示される。
- 保存した設定を編集後、再表示しても更新内容が維持される。
- 評価項目の重み合計が100%でない場合は保存できない。
- 項目追加型と反復型の両方で評価実績を設定できる。
- 反復型の複数実績が、各回の100点換算値の単純平均として集計される。
- 確認操作後に科目または評価項目を削除できる。

### 12.3 実績記録

- 出席実績を登録し、対象科目で確認できる。
- テストまたは課題の点数を登録し、対象科目で確認できる。
- 出席記録と点数記録を編集・削除できる。
- 他の利用者から対象データを閲覧・変更できない。

### 12.4 計算・表示

- 出席実績を更新すると、残り許容欠席回数へ反映される。
- 点数実績を更新すると、目標達成に必要な点数へ反映される。
- 計算に必要な変数が不足している場合、利用者が入力してから計算できる。
- 手動補完した変数は、明示的に保存しない限り再読み込み後の保存データへ影響しない。
- 必要出席率と最大欠席回数のうち、より厳しい条件で残り欠席回数が計算される。
- 残りの評価項目で必要な点数が100点換算の平均として表示される。
- 目標達成が不可能または計算不能な場合に、通常の必要点数と区別できる。
- ダッシュボードから注意が必要な科目を判別できる。
