# 技術スタック

## 全体構成

```text
ブラウザ
  ↓ HTTPS
Cloudflare Workers
  ↓ OpenNextがNext.jsのリクエスト処理へ変換
Next.js App Router
  ├─ Server Components / Server Actions
  ├─ 認証セッション更新（middleware.ts）
  └─ Supabaseクライアント
       ↓
Supabase Auth + Postgres + Row Level Security
```

画面表示とサーバー処理はNext.jsへ集約し、認証と永続化はSupabase、配信と実行基盤はCloudflare Workersが担当します。

## 採用技術とバージョン

バージョンは現在の `package-lock.json` に固定されている値です。

| 分類 | 技術 | バージョン | 主な役割 |
| --- | --- | --- | --- |
| フレームワーク | Next.js | 16.3.0 | App Router、Server Components、Server Actions、Route Handler |
| UIランタイム | React / React DOM | 19.2.8 | コンポーネントとクライアント操作 |
| 言語 | TypeScript | 5.9.3 | アプリケーション全体の型付け |
| CSS | Tailwind CSS | 4.3.3 | レスポンシブUIとスタイル |
| 認証連携 | `@supabase/ssr` | 0.12.4 | Cookieを使うサーバー側認証セッション |
| DBクライアント | `@supabase/supabase-js` | 2.112.0 | Auth、Postgres、RPCへのアクセス |
| デプロイアダプター | `@opennextjs/cloudflare` | 1.20.2 | Next.jsの出力をCloudflare Workers向けに変換 |
| Cloudflare CLI | Wrangler | 4.120.0 | ローカルプレビュー、型生成、デプロイ |
| テスト | Vitest | 4.1.10 | 計算、変換、クエリ、Server Actionの単体テスト |
| 静的解析 | ESLint | 9.39.5 | Next.js・TypeScriptコードの検査 |

Next.js 16.3.0の要件に合わせ、Node.jsは `20.9.0` 以上を使用します。

## アプリケーション層の責務

| 場所 | 責務 |
| --- | --- |
| `src/app/` | ルーティング、ページ構築、Server Action、Route Handler |
| `src/components/` | 表示とユーザー操作。機能領域ごとに分割 |
| `src/lib/calc/` | 出席回数と目標点数の純粋な計算ロジック |
| `src/lib/supabase/queries/` | Supabaseとの読み書きとレスポンス変換 |
| `src/lib/auth/` | 認証入力と利用者向けメッセージ |
| `src/lib/*` の機能別ディレクトリ | フォーム入力、集計、ドメイン変換 |
| `supabase/migrations/` | テーブル、RLS、制約、トランザクションRPC |

画面、フォーム、DBアクセス、計算を分離し、一ファイル一責務を基本とします。計算ロジックはUIやSupabaseへ依存させず、Vitestで直接検証できる構造です。

## 認証とデータ保護

- Supabase Authのメールアドレス・パスワード認証を使用する。
- セッションは `@supabase/ssr` を介してCookieで維持する。
- `/dashboard` と `/subjects` 配下は `src/middleware.ts` でセッションを更新・検証する。
- 全業務テーブルでRow Level Securityを有効にし、本人のデータだけを操作可能にする。
- 科目と評価項目の同時保存はPostgres RPCでトランザクション化する。
- `SUPABASE_SERVICE_ROLE_KEY` はアプリケーションへ渡さない。

Next.js 16では `proxy.ts` が推奨されていますが、現在使用しているCloudflareアダプターとの互換性を優先し、Edge Runtimeで動く `middleware.ts` を採用しています。アダプター更新時にはこの例外を再評価します。

## デプロイ構成

- `open-next.config.ts`: OpenNext for Cloudflareの設定
- `wrangler.jsonc`: Worker名、エントリーポイント、互換日、静的アセット設定
- `.open-next/`: OpenNextのビルド生成物。Git管理対象外
- `.wrangler/`: Wranglerのローカル状態。Git管理対象外

詳細な手順は [デプロイ.md](./デプロイ.md) を参照してください。

## 品質確認

変更後は少なくとも次を実行します。

```bash
npm run lint
npx tsc --noEmit
npm test
npm run build
```

Cloudflare固有の変更を含む場合は、さらに `npm run preview` でWorker環境を確認します。
