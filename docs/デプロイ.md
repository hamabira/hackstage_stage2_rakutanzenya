# Cloudflare Workersデプロイ

## 現在の構成

このアプリはOpenNext for Cloudflareを使い、Cloudflare Workersへデプロイします。

| 項目 | 値 |
| --- | --- |
| Worker名 | `rakutan-zenya` |
| エントリーポイント | `.open-next/worker.js` |
| 静的アセット | `.open-next/assets` |
| Compatibility Date | `2026-08-08` |
| Compatibility Flag | `nodejs_compat` |

設定の正本は `wrangler.jsonc` と `open-next.config.ts` です。公開URLはリポジトリ内に固定していないため、Cloudflare Dashboardまたはデプロイコマンドの出力で確認します。

## 前提条件

- Node.js `20.9.0` 以上とnpmが利用できる。
- CloudflareアカウントへWranglerでログイン済みである。
- 対象のSupabase環境にマイグレーションが適用済みである。
- `.env.local` に次の項目が設定されている。

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
GEMINI_API_KEY=
# 省略時は gemini-3.5-flash-lite を使う
GEMINI_MODEL=
```

値の扱いは接頭辞で分かれます。

| 値 | 公開範囲 | 保護の方法 |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ブラウザへ公開される | SupabaseのRLSでアクセスを制御する |
| `GEMINI_API_KEY` | サーバー専用。ブラウザへ出さない | Workerのシークレットとして保持し、Server Actionからのみ読む |

`GEMINI_API_KEY` は科目登録のAI解析（issue #49）で使います。`NEXT_PUBLIC_` を付けるとクライアントバンドルへ埋め込まれるため、絶対に付けないでください。`SUPABASE_SERVICE_ROLE_KEY` などのDB特権キーは引き続き設定しません。

AI解析はGoogle AI StudioのGemini APIを使います。無料枠では入力内容がGoogleのプロダクト改善に利用される規約のため、扱う文章の性質に応じて有料枠の利用を検討してください。またサーバー側のレート制限は未実装で、現状はクライアント側の二重送信防止のみです。一般公開する場合は先にレート制限を追加してください。

## 初回準備

```bash
npm install
npx wrangler login
cp .env.local.example .env.local
```

本番のWorkerへはAPIキーをシークレットとして登録します。`wrangler.jsonc` の `vars` は平文でコミットされるため、そちらへは書きません。

```bash
npx wrangler secret put GEMINI_API_KEY
```

`npm run preview` はWorkers相当の環境で動くため `.env.local` をバインディングとして読みません。ローカルでAI解析を試す場合は、リポジトリ直下の `.dev.vars`（gitignore済み）にも同じ値を書きます。

```env
GEMINI_API_KEY=
```

Supabase側では、使用する本番URLをAuthenticationのURL設定へ追加します。メール確認やOAuthを有効にする場合は、`/auth/callback` を使うリダイレクトURLも許可します。

## ローカルプレビュー

```bash
npm run preview
```

このコマンドはOpenNextのビルド後、WranglerでCloudflare Workers相当のローカル環境を起動します。通常の画面開発は `npm run dev`、デプロイ互換性の確認は `npm run preview` と使い分けます。

## 本番デプロイ

デプロイ前に品質チェックを実行します。

```bash
npm run lint
npx tsc --noEmit
npm test
npm run build
```

問題がなければデプロイします。

```bash
npm run deploy
```

`npm run deploy` はOpenNextのビルドとCloudflare Workersへの配布を続けて行います。成功時に表示されるWorker URLを開いて動作確認します。

## デプロイ後の確認

- 未ログインで保護ページを開くと `/login` へ移動する。
- 新規登録、ログイン、ログアウトが動作する。
- 科目の登録・編集・削除ができる。
- 科目登録画面のAI解析が成功し、下書きがフォームへ反映される。
- AI解析を使わない手動登録も従来どおり動作する。
- 出席記録と点数記録が保存される。
- 科目詳細とダッシュボードの計算結果が更新される。
- 別ユーザーのデータを取得・変更できない。
- Cloudflareのログに継続的な例外が出ていない。

## 設定変更時の注意

- Worker名や互換日を変える場合は `wrangler.jsonc` を更新する。
- OpenNextのキャッシュやバインディングを追加する場合は `open-next.config.ts` と `wrangler.jsonc` の責務を分けて更新する。
- `.open-next/`、`.wrangler/`、`.dev.vars`、`cloudflare-env.d.ts` は生成物またはローカル設定のためコミットしない。
- Cloudflare環境型が必要になった場合は `npm run cf-typegen` で再生成する。
- SupabaseのURL設定を変更した場合は、認証導線を本番URLで再確認する。

## 障害時

デプロイ後に問題が起きた場合は、Cloudflare Dashboardで直前のデプロイとログを確認します。緊急時はDashboardのデプロイ履歴から直前の正常バージョンへ戻し、原因修正後に再デプロイします。DBマイグレーションはWorkerのロールバック対象ではないため、アプリとDBの互換性を事前に確認してください。
