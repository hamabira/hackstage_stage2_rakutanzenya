# ドキュメント一覧

このディレクトリでは、要件・技術構成・運用手順・将来構想を責務別に管理します。初めて参加する場合は、README、要件定義書、技術スタックの順に読むと全体を把握できます。

| 文書 | 役割 | 更新するタイミング |
| --- | --- | --- |
| [../README.md](../README.md) | プロジェクト概要と最短のセットアップ | 主要機能、起動手順、入口となるリンクが変わったとき |
| [要件定義書.md](./要件定義書.md) | MVPの機能要件・非機能要件・受け入れ条件 | プロダクト要件を変更したとき |
| [技術スタック.md](./技術スタック.md) | 採用技術、バージョン、役割、アーキテクチャ | 依存技術や構成を変更したとき |
| [デプロイ.md](./デプロイ.md) | Cloudflare Workersへの配布と運用確認 | 配布先、環境変数、デプロイ方法を変更したとき |
| [データ整合性ルール.md](./データ整合性ルール.md) | フォーム・Server Action・DB制約の責務 | 入力検証、DB制約、マイグレーションを変更したとき |
| [MVP外機能.md](./MVP外機能.md) | MVPに含めない機能候補のバックログ | 将来機能を追加・採用・取り下げしたとき |

## 管理方針

- READMEには概要と導線だけを置き、詳細は責務に合う文書へ分ける。
- 実装状況はソースコードとテストを正とし、完了済み機能を「未実装」のまま残さない。
- パッケージの正確なバージョンは `package-lock.json` を正とする。
- DBの適用順と内容は `supabase/migrations/` を正とする。
- 公開URLや秘密情報は、必要な場合だけ安全な運用先で管理し、推測値を文書へ書かない。
